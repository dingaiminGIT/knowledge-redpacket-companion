# 0.4.1-rc1 播放控制权修复验收

## 原因与修改

- 旧监听器把任意课程标题变化当成官方自动换集，重新打开伴侣队列下一条；暂停后的官方播放还会自动激活伴侣队列。
- 现在只有伴侣中的主动播放操作和已确认播完后的衔接能够申请控制权。未请求的课程变化立即退出连播、停止守护并取消打开/播放重试，不向官方播放器发送暂停或换课指令。
- 升级前残留的连播标志不作为授权；官方恢复播放不自动恢复伴侣连播。
- 状态和标题回调使用当前 MediaController 快照，避免延迟的旧回调把正常切换误判为外部选择。
- 启动确认必须实际进入 PLAYING；短暂 PAUSED 等待 600 ms 再确认暂停，避免加载过程误退出连播。此等待不会主动恢复音频。

## USB 真机验证（2026-09-10）

设备：小米 2410DPN6CC / HyperOS，Android SDK 36。覆盖安装，保留用户缓存与配置。

- 伴侣连播期间，在得到「最近学习」点击《读红楼》播放：官方保持该内容 PLAYING，伴侣 active=false、suspended=false，控制权和重试目标清除；超过 10 秒没有抢回。
- 再打开伴侣而不点播放，官方内容不变，也没有恢复伴侣队列。
- 从伴侣主动重新启动连续播放后 active=true，正常播放「05｜内驱」。
- 用系统媒体暂停键暂停：保持 PAUSED，伴侣暂停连播；用系统媒体播放键恢复：官方 PLAYING，但伴侣不会自动激活。再次从伴侣启动连播成功。
- 把「05｜内驱」定位到末尾 7 秒，自然播完后进入伴侣下一条「046｜森川葵」，active=true；日志记录 PLAYING 确认耗时 248 ms。
- 末尾回归曾暴露旧 metadata 回调导致误退出的问题；改用当前快照后重测通过，并再次验证官方手动换课仍能让出控制。
- 再次定位「05｜内驱」末尾 7 秒并息屏：15:27:06.876 确认播完，15:27:07.075 确认「046｜森川葵」PLAYING，耗时 199 ms；检查时设备仍为 Dozing，active=true。仅为短时息屏回归，未重做长时间后台压力测试。
